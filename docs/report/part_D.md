# Competition & Temporal Analysis

## Competition Modeling

本模块回答“多人跨队关系如何随比赛时间变化”。竞争超边仍遵循统一超图契约：一条原始边至少关联三名不同球员、至少两支球队，且双方均有可追溯的参与事件。它表示一个有限片段中的事件关联推断，不等同于传统二元对抗边，也不能被解释为完整逐帧攻防站位。

提取时先按 `period + event_index` 恢复事件顺序，再按连续控球 ID 与阶段切段。以实际存在的 Pressure、Duel、Interception、Dispossessed 或 Ball Recovery 事件为锚点，使用中心前后各 2.5 秒的闭窗口。仅在该片段内收集记录中的发起球员与 Pass 明确记录的同队接球对象。参与者必须能够在球员名单与源事件中追溯；不通过坐标、球队名单、空间接近或球星身份补入球员。接球对象字段也不被用作成功接球的证据。

默认最多保留八名球员、二十四个上下文事件；超出则跳过整个窗口。缺失关键时间、顺序、身份或控球字段时不推测补全；时间倒退会切断连续性；不同阶段与点球大战不连接。边界与阈值是为控制误关联和视图复杂度采用的设计选择，尚待真实比赛数据验证。

每条边保留去重后的 `player_ids`、`team_ids`、有序 `event_ids`、准确起止分钟、`weight=1` 及 `evidence_type=event_window_inference`。完全相同的来源事件窗口只输出一次；同一球员组合在不同时间出现时保留为不同原始边。不同窗口允许重叠，故原始边数既不等于独立争抢次数，也不代表攻防强度。重复组合频率属于另一步聚合，不能改写原始边权重。

## Temporal Design and Interaction

统一状态保存关系模式、球队、球员与分钟浮点区间。Collaboration/Competition 按钮只切换 `mode`，由 B 的同一个主超图渲染器更换数据源；本模块不创建第二个竞争图。按钮采用文字标签、颜色与按下状态共同提示当前模式。

时间控制采用两个端点滑块及可输入的小数分钟框，最大值由已加载事件和超边计算。端点交叉时将另一个端点推至同一值，允许零宽区间；“查看全场”恢复比赛实际范围。超边过滤严格采用片段相交规则：`end_minute >= start && start_minute <= end`。因此片段横跨筛选边界时完整计一次，而非裁切成新边。C 的个人指标则按选定时间内的事件点重新计算，页面区分时段值与全场对照。

时间条额外显示每五分钟已记录的对抗事件数，帮助导航；它不表示无球跑位或完整对抗强度。界面持续提示事件推断的含义，在无边时解释证据不足、阈值过滤或当前时段为空，避免把缺失记录误解成比赛没有对抗。

## System Integration

页面通过本地 HTTP 读取冻结的五份 JSON。装配层检查结构、唯一 ID、球员球队引用、超边来源、参与者证据和时间一致性后，向 A/B/C/D 传入同一个 dataset 与 store。各模块只操作自己的容器。模式与时间变化通过订阅触发局部重绘，不重复调用挂载函数；退出时调用已提供的清理函数。

数据缺失或不符合契约时显示具体文件和原因；合法的空竞争数组允许加载。代码模块未交付时，其他可用模块保持工作。状态快照复制时间数组，非法更新被原子拒绝，相同更新不重复广播；退订与生命周期测试检查快速切换后没有重复界面。

## Results, Evidence and Limitations

截至 2026-10-28，本工作区没有 A 的真实事件/球员/统计，也没有 B 的正式超图主渲染器。正式 `competition_edges.json` 因缺少源证据而为 `[]`，不据此作出世界杯决赛的比赛解读。自动化验证使用明确标记的人工测试记录与 A/B 接口替身，现有 C 和 D 则使用实际模块。具体已运行结果见 `../TEST_RESULTS_D.md`。

可复现的实现案例是模拟窗口：第 60 秒 Mock Alpha 传球给明确记名的 Mock Beta，第 61 秒 Mock Opponent 有 Pressure 记录，第 62 秒 Mock Beta 有 Duel 记录。中心窗口包含三个来源事件，能够支持三人跨两队的事件关联。选择 `[1,1]` 分钟时，竞争超边因触及左端点而保留，C 面板记录一次该球员传球；选择 `[0,0]` 时无相关边且传球数为零。这个例子解释过滤语义，不是任何真实比赛事件。

可用截图：`../screenshots/module-d-missing-data.png` 展示真实缺失数据状态；`../screenshots/module-d-mock-integration.png` 与 `module-d-mock-mobile.png` 展示模拟联调，主图明确为接口替身。正式报告须在 A/B 交付后补充真实数据截图、事件 ID 和球星案例，不可把当前截图标为完整世界杯超图。

方法局限包括：事件稀疏、未观察到的无球球员、短窗口共现的误关联、控球边界导致的漏识别、窗口重叠以及阈值敏感性。结构校验不能证明数据来源真实；A 仍须核验来源与时间转换。后续应进行 3/5/8 秒窗口敏感性检查并报告保留/跳过数量，而非仅凭更多超边推断更强竞争。

## Conclusion Draft

本项目设计以统一超图结构表达多人协作与跨队事件关联，并通过模式、时间和球星选择建立跨视图探索流程。模块 D 提供可追溯的竞争边提取、统一状态和页面装配，强调来源证据与缺失解释。完成真实数据和 B 主视图联调后，才可评估其对具体比赛分析的帮助。未来可在许可与数据可用的前提下引入更完整的位置记录，并比较事件推断与追踪证据之间的一致性。
