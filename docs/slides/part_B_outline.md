# B 展示：三页，建议 2 分 50 秒

对应 `part_B.pptx`，每页备注含讲稿；时长是建议，成员本人需要计时排练。截图来自真实比赛页面，图形示意会明确标为示意。

## 第 1 页：一条边保留整个多人集合（45 秒）

画面：两两连线与三人包络的示意对照。球员节点用球队颜色；说明三人门槛是项目约定。回答“为什么使用超图”。

讲稿：我的部分解决的是，怎样把一段多人配合作为一个整体保留下来。普通传球图中的一条线只连接两个人；如果只展示两两关系，读者不容易知道哪些球员属于同一个事件片段。我们用一条包络表示完整成员集合，本项目要求至少三名不同球员。节点是球员，超边是有来源依据的片段，并且可以点击回到原始事件。这里的包络是关系布局，不是球员在球场上的位置。

## 第 2 页：从真实成功传球链生成超边（60 秒）

画面：比赛顺序 → 同队同控球 → 连通成功传球 → 有界窗口 → 三人及以上。默认最多 4 次传球 / 20 秒 / 5 人。显示 531 条原始协作边，三/四/五人分别 262/187/82。

讲稿：A 已提供真实比赛的规范化事件。我按比赛阶段和原始事件序号恢复顺序，只使用常规时间与加时赛。传球必须明确成功，下一位发起者要接上上一位传球对象；换控球、传球失败和时间异常都会切断链。每次最多取四次传球、二十秒、五名球员，去重后达到三人才生成超边。默认得到五百三十一条原始片段。每条保存源事件和起止时间，权重都是一；重复组合在展示时才合并。窗口会重叠，所以片段数不是独立进攻次数。参数由配置控制，报告还比较了两次、三次和四次传球的结果。

## 第 3 页：同一个主图，连接球星、证据与时间（65 秒）

画面：真实主图截图，突出 Messi 关联、包络编号、事件展开及双模式。

演示：C 选择 Messi → 主图高亮 → 点击一个组合并展开源事件 → 切 Competition → 缩小时间范围。现场时间不够时用截图展示对抗模式。

讲稿：选择 Messi 后，主图高亮相关组合，C 面板显示他参与八十一个协作片段。图上默认只显示前十二个完整组合，所有原始片段仍保留在统计和证据列表中。点击一个包络可以看到全部成员、时间和真实事件 ID，也能从图里点击球员反向更新个人面板。主图支持拖拽、缩放、平移和键盘选择。切换到对抗模式时，仍复用同一个 SVG，使用 D 提供的数据和虚线样式，明确提示这是事件窗口推断。球队、时间和球员都通过共享状态联动。我的交付包括协作算法、主图、测试和真实案例，AI 辅助实现与验证，最终人工审阅和排练由我完成。

## 问答准备

- 一条超边的参与者从哪里来？从有证据的成功 Pass 发起者与明确传球对象去重，不从全队名单或未知站位补人。
- `×N` 与 `weight=1` 是否矛盾？前者是前端完整组合频次，后者是每条原始片段权重；所有片段均可回溯。
- 为什么只显示 Top 12/24？控制包络拥挤，界面明确给出总数、显示数和关联优先规则，不改变 C/D 原始计数。
- 高参与数是否代表表现更好？不直接代表，受窗口重叠、控球量、上场时间和建模参数影响。
- 包络里包含其他球员怎么办？准确成员由选中节点高亮和完整成员表确定，包络形状仅辅助表达。
- AI 用于什么？依赖检查、算法/可视化代码、测试与源数据审计、截图、报告和展示草稿，实际个人审核另行记录。
